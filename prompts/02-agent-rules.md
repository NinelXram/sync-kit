# Phase 02 — Agent rules

You are installing sync-kit into this repository. The engine and `sync/` are in place. This phase adds a short,
engine-generated block to the files that coding agents read (e.g. `AGENTS.md`, `CLAUDE.md`), so every agent working
in this repository checks the sync inbox and writes a note when it changes a contract.

## Goal

Every agent rule file listed in `state.decisions.agentFiles` contains the sync-kit marker block, generated by the
engine.

## Preconditions

- You are at the repository root.
- Phase 01 is done: `node sync/scripts/sync.mjs state show` lists `"01"` under `phases`. If not, stop and tell the
  user to run `.sync-kit/prompts/01-install.md` first.

## Inputs

- `node sync/scripts/sync.mjs state show` — `decisions.agentFiles` (repo-relative paths).
- `sync/.kit/discovery.md` — agent rule files and per-folder rule files found in phase 00.

## Steps

1. **Read the decided files:** run `node sync/scripts/sync.mjs state show` and take `decisions.agentFiles`. Only these
   files may get the block — one per agent the team uses:

   | Agent | File that gets the sync-kit block |
   | --- | --- |
   | Claude Code | `CLAUDE.md` |
   | Codex and other agents that read `AGENTS.md` | `AGENTS.md` |
   | Cursor | `.cursor/rules/sync-kit.mdc` (always this new, dedicated file — never an existing `.mdc`) |
   | Gemini CLI | `GEMINI.md` |
   | GitHub Copilot | `.github/copilot-instructions.md` |

   - Drop any listed path that is not in this table (e.g. `.cursorrules`, an existing `.mdc`, a per-folder rule
     file) and treat it as a pointer candidate for step 3. For Cursor, always use `.cursor/rules/sync-kit.mdc`.
   - If the list is empty or missing, ask the user which agents the team uses and take their files from the table.
   - For every file that does not exist yet, tell the user it will be created and ask for confirmation. Drop the
     files the user rejects.
   - If the user wants no file at all (or rejects every file), record that and skip the phase, then go to step 3:
     ```
     node sync/scripts/sync.mjs state decide --no-agent-files
     node sync/scripts/sync.mjs state phase 02 skipped
     ```
   - Otherwise, if the final list differs from state, record it (one `--agent-file` per file, all files in one
     command — the list replaces the previous one):
     ```
     node sync/scripts/sync.mjs state decide --agent-file AGENTS.md --agent-file CLAUDE.md
     ```

2. **Write the block** into the files, one `--file` per path:
   ```
   node sync/scripts/sync.mjs agent-rules --file AGENTS.md --file CLAUDE.md
   ```
   The engine inserts the block between `<!-- sync-kit:start -->` and `<!-- sync-kit:end -->`, or replaces an
   existing block; text outside the markers is never touched, and the file keeps its BOM and line endings.
   Running it again is safe. A new `.mdc` file under `.cursor/rules/` gets the Cursor frontmatter automatically.
   If a file has a broken marker pair (a start without an end, an end without a start, or two blocks), the
   command exits `1`, names the file and changes nothing: show the user the markers and let them fix them by hand,
   then re-run.

3. **Pointer candidates** — other rule files listed in discovery or dropped in step 1 (e.g. `.cursorrules`,
   `.windsurfrules`, an existing `.mdc`, `BACKEND_RULES.md`, `apps/web/AGENTS.md`): ask the user whether to add
   **one line** to each, pointing to the sync rules. Write it in the config language (`lang` in
   `sync/sync.config.json`) and name the file(s) that actually received the block in step 2, for example with
   `lang: "en"` and `CLAUDE.md`:
   `Cross-side changes: follow the sync notes protocol in CLAUDE.md (sync-kit block) and sync/README.md.`
   With `lang: "vi"` write the same sentence in Vietnamese. If phase 02 was skipped, point only to `sync/README.md`.
   Add the line only to the files the user approves, at the end of the file, and change nothing else.

4. **Hand-written sync instructions.** If a file that received the block already contains sync instructions written
   by hand outside the markers (common when the repository had a sync system before the kit, e.g. a section that says
   to read `sync/INBOX.md` or to run `sync/scripts/sync.mjs`), show those lines to the user: agents now read both.
   Ask whether to keep them or remove them. Remove only the exact lines the user approves; change nothing else.

5. Show the user the diff of the changed files (`git diff` and the new files).

## Hard rules

- Generate the block only with `sync.mjs agent-rules`; never write or edit text between the sync-kit markers by hand.
- Do not change anything outside the markers in the agent rule files, except the single pointer line of step 3 and
  the removal of hand-written sync lines of step 4, each only when the user approved it.
- Never create an agent rule file the user did not confirm, and never put the block in a file outside the table of
  step 1.
- Never write `sync/.kit/state.json` by hand; only through `sync.mjs state`.
- Do not run `git commit`; only suggest it.

## Outputs

- The agent rule files from `decisions.agentFiles`, each with the sync-kit block.
- Optionally one pointer line in approved per-folder rule files.

## Verify

```
node sync/scripts/sync.mjs doctor --phase 02
```

Every line must start with `✓` and the exit code must be `0`. A `✗ … contains the sync-kit marker block` line means
step 2 missed that file: rerun step 2 with it.

## Handoff


Tell the user to review and commit the changed agent files, e.g. `chore(sync): add sync-kit agent rules`. Cloud agents (Codex cloud, Claude Code web) start every task from the pushed branch: either continue with the next phase in this same task, or commit and push this phase's output (including `sync/.kit/`) to the working branch before starting the next task.
